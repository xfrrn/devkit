# 后端日志开发规范 (Backend Logging)

> devkit · `packages/backend-logging`
> 状态：🚧 规划中（骨架待补）

---

## 定位

让日志成为**可观测性的地基**，而不是出问题时才翻的噪音堆。
跨后端项目可复用的：结构化、分级、采集与排障约定。

## 待覆盖方向（占位）

- **结构化日志**：JSON 输出、统一字段（trace_id / level / msg / ctx）、禁止字符串拼接。
- **分级约定**：DEBUG / INFO / WARN / ERROR 各自该记什么、不该记什么。
- **关键路径埋点**：入口、出口、外部调用、慢查询、异常。
- **采集与查询**：如何接入 ELK / Loki / 云厂商，如何按 trace 串联。
- **反模式**：打太多、打太少、敏感信息泄露、日志当监控用。
- **落地骨架**：对应语言的 logger 封装示例（待定：Go / Node / Java）。

## 复用方式

clone 本仓库 → 读本 README → 拷贝 logger 骨架进项目 → 按业务补字段。

> 待补充。编写时遵循根级 `docs/principles.md`，尤其是「可观测，可回退」「规范优先于代码」。
