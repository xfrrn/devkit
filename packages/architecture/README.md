# 技术框架 / 架构方法 (Architecture)

> devkit · `packages/architecture`
> 状态：🚧 规划中（骨架待补）

---

## 定位

技术选型与系统分层的**决策框架**，而非某个具体框架的使用教程。
帮助在新项目里快速回答：「该用什么、怎么分层、边界在哪」。

## 待覆盖方向（占位）

- **技术选型**：选型的评估维度（团队、生态、生命周期、成本），避免追新。
- **分层与模块边界**：表现层 / 领域层 / 基础设施层如何划分，依赖方向如何约束。
- **状态与数据流**：前端状态管理、后端数据访问的约定。
- **目录结构模板**：可直接拷贝的项目骨架（前 / 后端各一）。
- **反模式**：过度设计、过早微服务、把框架当架构。
- **落地骨架**：项目脚手架 / 目录树示例。

## 复用方式

clone 本仓库 → 读本 README → 按决策框架做选型 → 拷贝目录骨架起手。
